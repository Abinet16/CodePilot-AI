# Threat model

Everything that comes from a repository (source, comments, README, config, test output) and every GitHub issue body is **untrusted input**. Model output derived from it is also untrusted.

| Threat | Control | Where | Status |
| --- | --- | --- | --- |
| Model writes outside the workspace (`../`, absolute paths) | Path normalization + traversal rejection | `agent-core/path-policy.ts` | ✅ tested |
| Symlink planted in repo redirects a write outside the workspace | `realpath` of deepest existing ancestor must stay in workspace | `agent-core/path-policy.ts` | ✅ tested |
| Model edits secrets, `.git`, CI workflows | Denied segments, basenames, and prefixes | `agent-core/path-policy.ts` | ✅ tested |
| Model runs arbitrary shell commands | The model never names a command: checks are maintainer-configured profiles (allowlisted executable, args without shell metacharacters, timeout), validated on save and again before every run, executed with `execFile` semantics as the container entrypoint; the model only reads results | `agent-core/command-policy.ts`, `worker/checks/checks-stage.ts` | ✅ integration-tested |
| Infinite repair loop burns tokens/compute | Bounded repair budget; safety violations fail immediately | `agent-core/repair-policy.ts` | ✅ tested |
| Concurrent workers / cancel race corrupt state | Compare-and-set transitions in a transaction | `worker/task-state.ts` | ✅ integration-tested |
| Duplicate job delivery duplicates work | Deterministic job id per task and resume reason; pipeline resumes from persisted status; a plan stored before a crash is reused, not regenerated | `contracts/queue.ts`, `worker` | ✅ integration-tested |
| Forged webhook | HMAC-SHA256 over raw body, constant-time compare, verified before parsing | `api/github/webhooks.controller.ts` | ✅ integration-tested |
| Duplicate webhook delivery creates duplicate records | Delivery row inserted in the same transaction as its effects; PK conflict ⇒ `duplicate` | `api/github/webhook.service.ts` | ✅ tested with 5 concurrent deliveries |
| Hostile repository runs code during clone (hooks, filters, fsmonitor, submodules) | Fresh `git init --template=`, `core.hooksPath=/dev/null`, `core.fsmonitor=false`, no submodules, no user/system git config; analysis never executes repository code | `worker/git/git.ts` | ✅ tested |
| Repository symlink exfiltrates host files into the index | `core.symlinks=false` on checkout; walker uses `lstat`/`Dirent` and skips non-regular files; files opened with `O_NOFOLLOW`; workspace removal never follows links | `worker/git/git.ts`, `worker/analysis/{scan,workspace}.ts` | ✅ tested |
| Secrets in a repository end up in the database or model context | Secret files (`.env*`, keys, `.npmrc`, `.netrc`, …) are rejected by path before being opened; lockfiles, generated, binary, and minified files are skipped | `agent-core/analysis/file-filter.ts` | ✅ integration-tested |
| Installation token leaks via git | Token passed as a github.com-scoped `http.extraHeader` through `GIT_CONFIG_*` env vars: never in argv, the remote URL, `.git/config`, or logs; git gets a minimal environment | `worker/git/git.ts` | ✅ tested |
| Non-https remote or option injection through repo names | Owner, name, and branch validated against GitHub's character rules; `protocol.allow=never` except https; `--` before the remote | `github/app-client.ts`, `worker/git/git.ts` | ✅ tested |
| Huge or adversarial repository exhausts the worker | Size check before clone, shallow single-commit fetch, git timeout, caps on walked entries, indexed files, bytes, file size, and line length; stale workspaces swept at boot | `worker/analysis`, `agent-core/analysis` | ✅ tested |
| Analysis of a different commit than the one reported | SHA pinned once per task (compare-and-set), fetched by SHA, and `HEAD` verified after checkout | `worker/analysis/analyze-stage.ts`, `worker/git/git.ts` | ✅ integration-tested |
| Unbounded or malformed context reaches planning | Character, snippet, and per-file budgets; package validated by `ContextPackageSchema` on write and read; snippets rendered as text in the UI | `agent-core/analysis/context-builder.ts`, `api/tasks` | ✅ tested |
| Full-text query injection | Query terms reduced to `[a-z0-9]+` before `to_tsquery`, and passed as bound parameters | `agent-core/analysis/search-terms.ts`, `worker/analysis/retriever.ts` | ✅ tested |
| Task started or cancelled by a read-only collaborator | WRITE+ required to create or cancel; visibility through `repository_access`; unknown and forbidden tasks both 404 | `api/tasks` | ✅ integration-tested |
| Duplicate PR on retry | Idempotency key per task and patch with the opened PR as its result; existing PR looked up by head branch before creating; `pull_requests.task_id` unique; reproducible commit makes a repeated push a no-op | `worker/pull-requests/open-pr-stage.ts`, schema | ✅ integration-tested (outage, crash before and after GitHub answered) |
| Agent overwrites or pushes to a branch it does not own | Refspec fixed to `HEAD:refs/heads/codepilot/…`, checked against the branch policy and the default branch; `--force-with-lease=<ref>:` only creates; a branch found at another commit fails the task untouched | `worker/git/patch-ops.ts`, `worker/pull-requests/open-pr-stage.ts` | ✅ tested against a real git remote |
| PR opened without a human decision, or for a different patch | `READY_FOR_REVIEW → OPENING_PR` only through a WRITE+ request naming the verified patch version, compare-and-set, audited; always a draft; never marked ready, approved, or merged by the agent | `api/tasks` | ✅ integration-tested |
| PR body pings people, tracks readers, hides links, or overstates verification | Model and issue text neutralized (HTML escaped, mentions broken, images and links disabled); check table built only from the stored passing verification of that patch; limitations, repairs, and AI authorship disclosed | `agent-core/pull-request` | ✅ tested |
| Failed or cancelled task leaves a pushed branch behind | Permanent failure or cancellation after the push and before a PR deletes the pushed branch; transient failures keep it for the retry | `worker/pull-requests/open-pr-stage.ts` | ✅ integration-tested |
| Late, duplicated, or out-of-order PR webhooks corrupt state | Delivery id dedupe; reports older than the stored `github_updated_at` ignored; merged stays merged; only agent-opened PRs tracked; scheduled reconciliation for missed deliveries | `api/github/webhook.service.ts`, `agent-core/pull-request/state.ts`, `worker/pull-requests/reconcile.ts` | ✅ integration-tested |
| Credentials leak into queue payloads or logs | Jobs carry ids only; GitHub user token never persisted; installation tokens in memory only; audit metadata redacted (sensitive keys and token patterns) | `contracts/queue.ts`, `api/audit/redact.ts` | ✅ tested |
| Install scripts exfiltrate secrets / reach network | Install must be `npm|pnpm|yarn install|ci` with `--ignore-scripts` (or `--mode=skip-build`), enforced by policy; it is the only step with network; no container ever receives credentials, the database URL, model keys, or the worker's environment | `agent-core/command-policy.ts`, `sandbox-runner` | ✅ tested |
| Repository code (tests, scripts, dependencies) attacks the host or other tenants | One fresh container per command: `--network none`, non-root, read-only root, `--cap-drop ALL`, `no-new-privileges`, memory without swap, CPU, pids, and open-file limits, size-limited `/tmp`, only the workspace and a per-verification cache mounted, never the Docker socket; containers labeled, removed after each run, swept at startup | `sandbox-runner/docker-sandbox.ts` | ✅ tested against real containers |
| Runaway test consumes CPU, memory, or time | Container limits; wall-clock timeout kills the container and fails the task as a safety violation; memory-limit kills fail the task; stage timeout above all of it | `sandbox-runner`, `worker/checks/checks-stage.ts`, `agent-core/repair-policy.ts` | ✅ tested |
| Check output floods the worker or leaks secrets into storage, UI, or the model | Head-and-tail capture in bounded memory; ANSI and control characters stripped; token-shaped secrets masked; stored summary bounded; rendered as text; fenced as untrusted when given to the model | `sandbox-runner/bounded-output.ts`, `agent-core/checks/output.ts` | ✅ tested |
| Checks run on something other than the patch under review | Workspace rebuilt from `base_sha` plus the stored diff; nothing runs unless the tree equals the patch's stored tree SHA; results linked to the patch version | `worker/git/source.ts`, `worker/checks/checks-stage.ts` | ✅ integration-tested |
| A collaborator with write access changes what executes | Configuring checks requires `MAINTAIN`; every change audited with the commands | `api/repositories` | ✅ integration-tested |
| Repair loop weakens tests or escapes the plan | Repairs are bounded per plan; edits limited to `planForRepair(plan)`; cumulative diff from the base must stay within the plan's files and change kinds; the prompt says to decline rather than weaken or delete tests | `worker/patching/repair-stage.ts`, `agent-core/patching` | ✅ integration-tested (scope); prompt by design |
| Prompt injection in repo files, issue bodies, or reviewer notes | Every untrusted input is fenced in `<untrusted-NONCE>` blocks whose closing tag carries a random per-request nonce, so content cannot forge the end of its block; the system prompt is fixed and states that fenced text is data; the model has no tools, only a JSON answer constrained by a schema; its paths are checked by the path policy and against the pinned commit; a human approves the plan before any code is written | `agent-core/planning`, `worker/planning` | ✅ tested (fencing, path checks); review gate integration-tested |
| Model output smuggles unsafe paths or oversized content into a plan | Structured output, then Zod limits (files, steps, lengths), path policy, existence check per change kind; invalid output is fed back for a bounded number of attempts, then the task fails | `agent-core/planning/{output-schema,plan-review}.ts` | ✅ tested |
| Runaway model spend | Per-task token budget checked before every call; bounded attempts per planning round; at most 3 plan versions per task; per-stage wall-clock timeouts; every call recorded in `agent_runs` and priced in `usage_records` | `worker/planning/plan-stage.ts`, `worker/patching/patch-stage.ts`, `worker/runs.ts`, `worker/pipeline.ts` | ✅ integration-tested |
| Cancelled task keeps spending | Worker polls for cancellation and aborts the in-flight model call or git fetch; the run is recorded as cancelled | `worker/cancellation.ts` | ✅ tested |
| Plan approved by a read-only collaborator, or a stale plan approved | WRITE+ required; approval names the version and is a compare-and-set on the plan awaiting review; both reviews are audited | `api/tasks` | ✅ integration-tested |
| Patch changes files the reviewer never approved | Every patched file must be in the approved plan with the same change kind; skipped planned files are recorded and shown; the commit stages only the validated paths and fails if `git status` shows anything else; the committed diff's paths and kinds must match the validated set | `agent-core/patching/patch-review.ts`, `worker/git/patch-ops.ts`, `worker/patching/patch-stage.ts` | ✅ integration-tested |
| Patch edits a symlink, submodule, or binary to reach outside the repo | Only tracked regular files (`100644`/`100755`) are edited; checkout uses `core.symlinks=false`; each write re-resolves the path with `realpath`; new files are created with `O_EXCL`; binary content and binary diffs are refused | `worker/patching/workspace-files.ts`, `worker/git/patch-ops.ts` | ✅ tested |
| Model edit lands in the wrong place | Find/replace edits must match exactly once, in order; failures are fed back instead of guessed | `agent-core/patching/apply-edits.ts` | ✅ tested |
| Oversized patch overwhelms review or storage | Per-file size limit, changed-line limit, and diff size limit; an oversized attempt is reset and sent back | `agent-core/patching/patch-review.ts` | ✅ integration-tested |
| Agent commits to the default branch or a human's branch | Branch is `codepilot/<slug>-<task id>`, slug reduced to `[a-z0-9-]`, checked by pattern, `git check-ref-format`, and against the default branch; reserved once per task; unique per repository; nothing is pushed in this stage | `agent-core/branch-policy.ts`, `worker/patching/patch-stage.ts` | ✅ tested |
| Commit metadata spoofs a person or injects trailers | Fixed author and committer identity from config (unroutable default address); the subject is one line of at most 72 characters without control characters; the body is stripped of control characters; task trailers come last | `contracts/patch.ts`, `worker/patching/patch-stage.ts` | ✅ tested |
| Stored patch differs from what was reviewed later | Diff stored with its SHA-256 and the commit's tree SHA; applying the diff to `base_sha` must reproduce the tree; attempts are versioned, never overwritten | `worker/git/patch-ops.ts`, schema | ✅ integration-tested |
| Model-written code rendered as HTML | Diffs and summaries are rendered as text nodes only | `web/tasks/[id]/diff-view.tsx` | ✅ by design |
| Model API key leaks | Read only by the worker from its environment; never sent to the API, web app, queue, or database; the Gemini key travels only in the `x-goog-api-key` header, never in a URL or error message | `worker/config.ts`, `worker/model` | ✅ tested |
| Repository code sent to a model provider is retained or used for training | Provider is an explicit operator choice (`MODEL_PROVIDER`); Gemini free-tier data use is documented in `.env.example`, the README, and ADR 0009; Ollama keeps everything on the machine | `worker/model/factory.ts` | ✅ documented |
| A local model acts on a silently truncated prompt | Ollama's context window is always set; an answer whose prompt did not fit with room to reply is refused | `worker/model/ollama-model.ts` | ✅ tested |
| Cross-tenant repository access | Access derived only from the user's own GitHub token; every query scoped through `repository_access`; unknown and forbidden look identical (404) | `api/repositories` | ✅ integration-tested |
| Stale access after GitHub revocation | Missing grants deleted at each sign-in; removal and uninstall webhooks revoke immediately | `api/github` | ✅ integration-tested |
| Webhook used to grant access | Webhooks only record state and remove access | `api/github/webhook.service.ts` | ✅ by design + tested |
| Login CSRF / OAuth code injection | Random `state` bound to an HttpOnly cookie, constant-time compare | `api/auth` | ✅ integration-tested |
| Open redirect after login | `returnTo` restricted to same-origin paths; re-sanitized on decode | `api/auth/oauth-state.ts` | ✅ tested |
| Session theft from DB leak | Only SHA-256 of session tokens stored; sessions revocable and expiring | `api/auth/session.service.ts` | ✅ integration-tested |
| Cross-site mutation (CSRF) | Same-origin `/api` proxy, `SameSite=Lax` cookie, JSON-only bodies | web + api | ✅ by design |
| Setup URL `installation_id` spoofing | Parameter ignored; access re-derived via login | `api/github/github.controller.ts` | ✅ tested |
| Bearer token sent to another host via pagination | `Link: rel=next` followed only to `https://api.github.com/` | `api/github/github.client.ts` | ✅ tested |

> The worker drives the Docker daemon, which is root-equivalent on its host: keep nothing else of value on that host. A standard Docker container is not a complete security boundary for hostile code. For public multi-user access the sandbox must use a hardened runtime (gVisor, Firecracker, or a dedicated isolated worker pool).
